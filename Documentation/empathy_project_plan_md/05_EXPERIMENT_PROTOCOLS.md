# Experiment protocols (reconciled, enforceable)

Use this as the mandatory protocol for defensible and reproducible results.

---

## 1) Split policy (must declare explicitly)
Every experiment must declare a split manifest ID.

### Manifest A: current repo default (Current repo verified)
- Training: stories `2,4,5,8` across subjects `1..10`
- Validation: story `1` across subjects `1..10`

### Manifest B: paper-comparison (Target state)
- Only use if intentionally rebuilt and fully documented.
- Must not be mixed with Manifest A in any metric table.

Rule:
- Every reported metric row must include `manifest_id`.

---

## 2) CCC implementation policy
- Maintain one canonical CCC implementation module.
- All streams and fusion must import that same implementation.
- Add tests for:
1. `CCC(x, x) == 1` (numerical tolerance).
2. Constant-sequence handling (no divide-by-zero failures).

---

## 3) Prediction alignment policy
For each stream, explicitly document:
1. Window length.
2. Stride.
3. Label assignment point.
4. Frame-level reconstruction rule.

Fusion consumes only frame-level predictions generated by these declared rules.

---

## 4) Prediction artifact schema (target contract)
Per stream output should follow one schema, e.g.:
- `frame_idx`
- `timestamp_s` (optional)
- `y_pred`
- `y_true` (optional for non-eval runs)
- `split`
- `subject_id`
- `story_id`
- `manifest_id`

If a stream currently emits `.npy`, conversion to schema-compliant CSV must be part of the run.

---

## 5) Run artifact requirements
Every run folder must contain:
- config snapshot
- git commit hash
- metrics JSON
- run log
- produced prediction artifacts
- generated tables/plots used for reporting

---

## 6) Required ablations
- Stream-only results for all five streams.
- 3-stream vs 5-stream fusion.
- Postprocessing on/off:
1. low-pass
2. per-subject scaling
- Weighting:
1. equal
2. fixed/manual
3. CCC-proportional

---

## 7) Debug protocol for suspiciously high CCC
If a result looks too good:
1. Recheck split overlap and manifest assignment.
2. Verify train-only fitting of normalization/scaling.
3. Verify window-to-frame alignment and shift assumptions.
4. Recompute CCC with canonical implementation.

---

## 8) Reporting protocol
All final tables and plots must include:
- manifest ID
- modality list
- postprocessing settings
- weighting strategy
- artifact path reference
